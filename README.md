## What is this?
We’ve noticed a growing trend that is quietly killing the joy of computing in DoCSE at KU: the pressure to be "innovative." We are told that every project must be a "startup idea" or a "unique solution" to a global problem. For a student still mastering the fundamentals, this is a distraction. It turns curiosity into a chore and deep learning into a search for market-fit.

The goal is simple: Zero Innovation, Maximum Understanding. We don't want "new ideas"; we want you to rebuild the foundations of Computer Science to see how they actually work.

So, we're launching a curated `Project Reference List` focusing on---but not limited to 1st/2nd year DoCSE students.

## What This Repository Is NOT

This repository is intentionally opinionated.

It is **not**:

### Not a Startup Idea Generator
You will not find SaaS ideas, app concepts, or business proposals here.  
The goal is understanding systems, not building products.

### Not a Framework Showcase
This is not a collection of projects designed to demonstrate modern frameworks or libraries.  
High-level abstractions are often avoided rather than embraced.

### Not a Beginner Tutorial Collection
This repository does not replace courses, textbooks, or structured teaching material.  
Projects assume curiosity, experimentation, and self-driven learning.

---

If a project idea can be summarized as:
> “Build an app that already exists, but with a new feature”

it likely does not belong here.

If a project forces you to ask:
> “How does the computer actually do this?”

then it probably does.


## How to Use This Repository

Do not pick projects based on popularity or technology trends.

Pick a project that challenges something you cannot yet explain clearly.

Start small.  
Go deeper gradually.

---

## Contributing

This repository grows through community contributions.

If you want to suggest a project:

1. Open a **Project Suggestion** issue.
2. Follow the provided template.
3. Maintainers review based on educational value.
4. Approved projects are added to the list.

### Contribution Rule

Projects are accepted based on **learning depth**, not novelty.

---

## Why This Exists

Many students feel they must build something impressive before understanding how computers work.

This repository exists to reverse that idea.

Understanding comes first.  
Innovation can wait.
